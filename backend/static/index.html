User Guide

A simplified, step-by-step guide to the SP PH Truck Booking Centralised Operations template, written for user testing. It covers every feature currently in the app. Every role except New User can open this page. Click a topic below to jump straight to it.

1. Getting started

  1. Open the app URL in your browser and sign in with your company Google account — there is no separate password.
  2. Look at the menu on the left. It shows only the pages your role is allowed to use, grouped under Main, Operations, Vendor Operations, Master Data and Administration. The User Guide page (this page) is available to every role except New User.
  3. Your name, avatar and current role appear at the top right. Click the avatar to open Account or Sign out.
  4. Click any menu item to open that page. The Dashboard opens first.
  5. If you see an orange Local Mode — Data not saved badge, you are running the app on a computer with no database: everything works, but records disappear when the server restarts. On the deployed site, data is kept permanently.
  6. If a page you expect is missing, your role has not been granted it yet — a Master Admin can add it (see topic 15).

2. Dashboard

  1. Use the Filters card: Final Call From / To, Account, Department, Status, Origin Port, Destination Port and MAWB.
  2. Click Apply Filters (or Refresh in the header) to refresh the figures and the list.
  3. Read the summary stat cards on top for request counts at a glance.
  4. Scroll down to Recent Requests for the latest activity; click the Delivered Date header to sort it.

3. Creating a truck request

  1. Open New Request in the menu. The Booking Date is set automatically to today.
  2. Fill the common fields: Department (required), and optionally Origin Port, International MAWB and Domestic MAWB. Filling a MAWB or Origin Port here auto-applies it to the request below.
  3. The request needs: Account, Origin Port and Destination Port (they must be different), Packaging, Qty (at least 1), plus the dates and weights you want to track: Initial Call datetime (TBC), Customs Cleared, Pickup, Delivery, weight/volume and special instructions.
  4. Click Submit Request to save it. Any missing required field is pointed out in a message.
  5. Creating many requests at once — CSV upload: click Download CSV template to get a CSV file with the exact columns and one example row showing the format. Fill it in Excel or Google Sheets — one row per request, any number of rows (up to a 10 MB file) — then pick the file.
  6. A preview appears with a summary (rows in file / ready to create / cannot create) and every problem explained per row. Fix problem rows in your file and upload again if needed, then click Create N requests.
  7. The creation summary reports how many requests were created and, for any row that could not be created, exactly why. Rows in a batch are independent — one bad row never blocks the others.
  8. After saving, find the new requests on the Masterlist with status Pending and on Pending Allocation to Vendors.
  9. To attach documents (e.g. proof of delivery): open the request from Masterlist, use Edit (pencil icon) and add files in the attachments section — up to 8 files, 25 MB in total.

4. Masterlist — find, check and organise requests

  1. Use the search box to find a request number or name, and the filters below it: Status, Account, Dept, Origin, Destination, Truck Type, Vendor, Truck Plate, Trip ID, MAWB, Manifest, Booking From/To, Final Call From/To and Initial Call From/To.
  2. The first 7 columns (Request #, Actions, Requestor, Manifest, Status, Account, Dept) stay frozen on the left while you scroll the rest of the table sideways.
  3. Sort by clicking any column header with a sort arrow (Request #, Account, Qty, Trip ID, dates, Manifest, ...).
  4. Arrange the columns: drag a column header left or right to reorder the table. Your order is remembered — click Reset Columns in the header to restore the default layout.
  5. Compare Initial Qty (what the trip was created with) against Revised Qty (the current value). Initial Qty never changes after creation.
  6. For allocated requests you also see the Trip ID, the Drop # (use the up/down arrows to renumber drops within a trip) and the Distance (KM) in red.
  7. The Manifest column shows a red Missing Manifest when no manifest file has been uploaded for a request — click it to open Edit and upload one. Uploaded manifests show Uploaded in green with a Download CSV link containing the International MAWB, Domestic MAWB and every bag/carton/gunny/sack ID. Use the Manifest filter (Missing / Uploaded) or click the Manifest header to sort.
  8. Uploading a manifest: open Edit (pencil icon) → Manifest section. One Excel file (.xlsx/.xlsm) per request, max 5 MB; delete the current file first if you need to replace it. The key column (header containing bag, carton, gunny or sack, or a standard ID header) is extracted into unique IDs. The CSV download lists them with the request's MAWBs.
  9. Use the Actions column: View for full details and attachments, Edit (pencil) to update fields, status, quantity, truck plate, attachments and the manifest, and Delete (trash) when permitted.
  10. The Updated At column shows when the request last changed. All times shown in the Masterlist are GMT+8.
  11. Click Export CSV to download the current list, use your browser's Print (Ctrl+P) for a PDF, and page through results with the buttons at the bottom. Master Admins additionally see Clear All.

Statuses: Pending → Allocated → In Transit → Delivered. You can also set On Hold, Cancelled or Foul Trip from Edit.

5. Allocating requests to vendors (Pending Allocation)

  1. Open Pending Allocation to Vendors. Waiting requests are grouped by origin port and time window. Use the MAWB box at the top to narrow the list.
  2. Tick the requests you want to send together. Select All selects everything with the same origin port — only requests sharing an origin can go on one trip (a notice appears if you mix origins).
  3. Watch the green Consolidation suggestion banner: it proposes a combination and truck type that reaches a good utilisation percentage. Click Select these to take the suggestion.
  4. Step 1 — Drop order (appears when destinations differ): drops are suggested automatically by shortest distance; the distance between stops is shown in red. Change any number manually or click Re-suggest order.
  5. Step 2 — Truck type: pick the truck. The Trip Utilisation box shows the load against the truck's max capacity: red <70%, yellow 70–85%, green >85%. Overload and weight/volume warnings appear in red above the panel.
  6. Step 3 — Vendor: vendors are pre-sorted with the cheapest matching rate first. If a truck type has no max capacity set, add it in Master Library → Truck Types.
  7. Step 4 — Final Call datetime: required. Pick the date/time.
  8. Click Allocate to Vendor. You get a confirmation with the new Trip ID, the requests get drop numbers, and they leave this page.
  9. Changed your mind? Edit a request on Masterlist and set its status back to Pending — it returns here and the remaining drops renumber automatically.

6. Fleet Management

  1. Open Fleet. Admins and vendors see the Add Truck button; vendors see only their own trucks.
  2. Click Add Truck and fill plate number, truck type, driver, phone and vendor (when choosing for them).
  3. Filter the list by Availability, Vendor or Truck Type, and sort by clicking the headers.
  4. Use the Actions column to edit a truck or flip its Availability (Available / Not Available). Allocated trucks can be released by setting them available again after their requests are done.
  5. The Current Requests column shows how many open requests each truck is carrying.

7. Vendor Truck Assignment

  1. Open Vendor Truck Assignment (available to Admin, Master Admin and vendor roles).
  2. The table lists trips awaiting a truck with their trip ID, drops and origin.
  3. Click the truck dropdown on a row and pick an available truck of a suitable type, then confirm the assignment.
  4. Click Refresh to update the list; a notice appears when a trip is assigned, cancelled or already taken.

8. Rate Management

  1. Open Rates and click Add Rate.
  2. Choose the Vendor, Truck Type, Origin Port and (optionally) Destination Port, then enter Rate/Trip, the Foul Trip %, fuel surcharge and the Effective and Expiry dates.
  3. Use the search box and the Origin / Dest filters to find a rate; edit or delete it from the Actions column.
  4. Rates feed the vendor sorting on Pending Allocation (cheapest first), the cost estimates in Cost Analysis and the Foul Trip % shown on Foul Trip Review.

9. Vendor Speed Performance

  1. Open Evaluation. Filters: search by request #, Vendor, Truck Type, Plate, Origin, Destination, Account, Department, MAWB and Final Call From/To.
  2. The table shows every trip with its timing columns highlighted in blue — Customs to Arrival, and the other leg-to-leg lead times — next to request, trip and drop details.
  3. Click any sortable header to rank the vendors, and use Export CSV to download the current view.

10. Cost Analysis

  1. Open Cost and choose the Final Call From / To range (required), plus Account, Department, Origin, Destination, Vendor, Status or MAWB if needed.
  2. Click Generate Report. You get summary stat cards, a Vendor Share card showing each vendor's share of Delivered + Foul Trip requests, and the Detailed Breakdown table with every cost column (Actual Cost, Toll Fee, Management Fee, Fuel, Foul Trip Cost, Fuel Surcharge, Total Cost, ...).
  3. Only Delivered and approved Foul Trip requests count towards the figures — approve foul trips on Foul Trip Review first.
  4. Sort by clicking headers, drag column headers to reorder (remember — Reset Columns restores them), and click Export CSV to download. Admins also get Bulk Cost Update to fill cost fields for many requests at once.

11. Foul Trip Review

  1. Set a request's status to Foul Trip from Edit on the Masterlist. You must fill Foul Trip Count Confirmation (1 or 2) — the save is refused without it.
  2. Open Foul Trip Review. The list shows all foul trips with the count confirmation, rate, foul trip %, date and reason.
  3. Check the row, then press the green tick in the Approve column to approve it. Approved trips are the ones counted in Cost Analysis.
  4. Sort by any sortable column, use Refresh for the latest, and Reset Columns if you have dragged columns around.

12. Trip Utilisation Review

  1. Open Trip Utilisation Review. One row per trip with its Requests, Origin, Department, Vendor, Truck Type and Capacity (units).
  2. Compare Initial Utilisation % (quantities when the trip was created) with Revised Utilisation % (current quantities). Both convert packaging to a single base unit using Master Library → Capacity Conversion and divide by the truck's max capacity.
  3. Colours: red <70%, yellow 70–85%, green >85%.
  4. Filter by Final Call From/To, Department, Origin Port, Vendor and Truck Type; the summary cards on top show the averages. Click headers to sort and Refresh to reload.

13. Master Library — the reference data

Open Master Library and use the tabs. Add / edit / delete entries with the buttons on each tab.

  1. Ports — origin/destination ports. The map preview shows where a port is; click the map to set its coordinates (used for the distance and drop-order suggestions).
  2. Accounts, Departments, Packaging, Statuses — the dropdown values used across the app.
  3. Truck Types — name plus Max KG, Max CBM and Max Capacity (base units). The Max Capacity drives the Trip Utilisation %; if it is missing you get a warning on Pending Allocation.
  4. Vendors — vendor companies; each vendor also gets a login role named Vendor - <name>.
  5. Capacity Conversion — pick the base packaging unit (everything is measured in it, e.g. Pallet) and a factor for every other packaging type: how much of the base unit one unit of that type is worth (Carton 0.02 = 50 Cartons make 1 Pallet). The base unit is always factor 1.0. Utilisation on Pending Allocation and Trip Utilisation Review uses these factors — click Save after changing them.

14. User Roles

  1. Open User Roles (Admin and Master Admin). Every signed-in user is listed with name, email and role.
  2. Change a user's access with the Role dropdown: Viewer, Normal User, Admin, Master Admin, New User (no access) or a Vendor role. The change takes effect on their next page load.
  3. A Master Admin can also change their own role from the dropdown on their own row — the page reloads with the new permissions straight away. Note: once you switch away from Master Admin, only another Master Admin can switch you back.
  4. Admins cannot change their own role, and only Master Admins can assign the Master Admin role.
  5. Click a user's name to rename it (Admin+), or the red minus to remove the user.

15. Role Visibility (Master Admin only)

  1. Open Role Visibility. Each card is one role with a checkbox for every page in the app.
  2. Tick the pages that role should see, then click Save Changes. Users pick up the change on their next page load.
  3. Click a role heading to rename how the role is displayed everywhere (e.g. rename "Normal User" to "Dispatcher").
  4. New User always starts with no pages — that is the "waiting for access" state. The User Guide page is granted to every role automatically and cannot be switched off.

16. Quick reference

Utilisation colours (Pending Allocation and Trip Utilisation Review): <70% red under-filled   70–85% yellow OK   >85% green well loaded.

Status flow: Pending (waiting for allocation) → Allocated (on a trip) → In Transit → Delivered. Other statuses: On Hold, Cancelled, Foul Trip (needs the 1 or 2 count confirmation).

Trip IDs look like TNP-0001 (TNW, TCW, TSH follow the truck type). The number is frozen once assigned — requests may leave and rejoin a trip, but numbers are only renumbered for the remaining drops.

Consolidation badge: requests that were grouped onto one trip show it on Masterlist.

Distance (KM) is calculated and shown in red once a request is part of a trip.

17. Testing tips and troubleshooting

  • A page is missing from the menu — your role does not have it. A Master Admin grants it under Role Visibility (topic 15).
  • "No pages available" — your account is New User; ask an admin to change your role.
  • Orange Local Mode badge — the app is running on a test computer with no database; data resets on restart. On the live site this badge does not appear.
  • Attachments fail — limit is 8 files and 25 MB per request.
  • No utilisation % on Pending — the truck type has no Max Capacity (Master Library → Truck Types) or a packaging type has no factor (Capacity Conversion tab).
  • No distance between drops — port coordinates are missing (Master Library → Ports — click the map to set them).
  • Cost Analysis shows no figures — check the required Final Call date range and remember only Delivered and approved Foul Trip requests count.
  • Testing an error — if something fails, the page shows the exact error message; tell the administrators what it said and on which page.
